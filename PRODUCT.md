# Product

## Register

product

## Users

Information workers, builders, operators, and researchers who need to scan multiple public sources quickly. They use the dashboard to understand what is rising now, compare source-specific rankings, and decide which items deserve attention.

## Product Purpose

Information Radar collects hot lists, RSS feeds, GitHub, Hacker News, and related sources into a local dashboard. The overview page must preserve source/category rankings as the primary working surface, followed by global synthesis and collection health.

## Brand Personality

Calm, efficient, and precise. The interface should feel like a focused monitoring tool: light, readable, restrained, and quietly capable.

## Anti-references

Do not turn the overview into a marketing landing page, decorative big-screen display, neon dark dashboard, or generic SaaS card mosaic. Avoid loud gradients, oversized hero blocks, ornamental motion, and layout changes that move source/category rankings below global summaries.

## Design Principles

1. Source rankings first: the user should see category/source boards before synthesis.
2. Dense but calm: preserve high information density while keeping typography and spacing breathable.
3. Ranking clarity over decoration: numbers, titles, source names, metrics, and freshness should be easy to scan.
4. Motion as feedback: hover and refresh states should feel smooth and quiet, never performative.
5. Familiar tool affordances: use predictable panels, buttons, focus states, and restrained color.

## Accessibility & Inclusion

Aim for WCAG AA contrast, visible keyboard focus, reduced-motion-friendly transitions, and stable layouts that do not rely on color alone for state. Text should remain readable in Chinese and English labels without overflow.
